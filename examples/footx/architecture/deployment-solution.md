## 对比详情

### Vercel vs Cloudflare Pages

| 维度 | **Vercel** | **Cloudflare Pages** |
|------|-----------|---------------------|
| **与 Supabase 配合** | ⭐⭐⭐ 官方集成，一键部署 | ⭐⭐ 需手动配置环境变量 |
| **全球 CDN** | ⭐⭐⭐ Edge Network 160+ 节点 | ⭐⭐⭐ 300+ 节点，更快 |
| **构建速度** | ⭐⭐⭐ 快，缓存优化好 | ⭐⭐ 一般 |
| **React/Vite 支持** | ⭐⭐⭐ 原生支持，零配置 | ⭐⭐ 支持，但需配置 |
| **Serverless Functions** | ⭐⭐⭐ 与前端同仓库，路径 `/api` | ⭐⭐ 支持（Workers），但分离 |
| **自定义域名** | ⭐⭐⭐ 免费，自动 HTTPS | ⭐⭐⭐ 免费，自动 HTTPS |
| **价格（免费档）** | 100GB 带宽/月 | 无限请求 + 500 构建/月 |
| **团队功能** | ⭐⭐⭐ Preview Deployments 完善 | ⭐⭐ 基础 |
| **分析监控** | ⭐⭐⭐ 内置 Analytics | ⭐⭐ 基础 |

## 选择 Vercel 的原因

### 1. 开发体验最佳

```
git push → 自动构建 → Preview URL → 合并后自动部署
```

Vite + React 项目可以零配置部署。

### 2. 与 Supabase 深度集成

- 官方模板直接支持 Supabase
- 环境变量自动同步
- 文档完善，社区活跃

### 3. 预览环境对团队协作很重要

- 每个 PR 自动生成预览链接
- 设计师/产品可以直接预览效果
- 方便 Code Review

### 4. Serverless Functions 方便

如果需要一些轻量 API（如 webhook 转发），可以直接写在项目里：

```
/api/stripe-webhook.ts
/api/health-check.ts
```

### 5. React 生态原生支持

- 基于 React 团队开发的 Next.js，对 React 项目优化最好
- 自动代码分割、图片优化
- Edge Functions 支持 React Server Components

---

## Cloudflare Pages 的优势（备选理由）

如果未来需要切换到 Cloudflare Pages，主要优势是：

1. **全球 CDN 节点更多**（300+ vs 160+），某些地区可能更快
2. **免费档无限请求**，Vercel 免费档有 100GB 带宽限制
3. **Workers 生态**，如果大量依赖 Cloudflare Workers

但对于 Foot X 初期阶段，Vercel 的开发体验优势更重要。

## CI/CD 流程

```
开发者推送代码到 GitHub
        ↓
  Vercel 自动触发构建
        ↓
  ┌─────────────────┐
  │  安装依赖       │
  │  pnpm install   │
  └─────────────────┘
        ↓
  ┌─────────────────┐
  │  构建项目       │
  │  vite build     │
  └─────────────────┘
        ↓
  ┌─────────────────┐
  │  生成预览链接   │
  │  Preview URL    │
  └─────────────────┘
        ↓
  PR 合并到 main 分支
        ↓
  自动部署到生产环境
```
